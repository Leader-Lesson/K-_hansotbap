# F7 TBM 전달 확인

- 상태: 미반영
- 브랜치: `feat/F7-tbm-check`
- 바뀐 곳: `app/backend/schemas.py`에 `TbmItemKind`, `TbmItem`, `TbmChecklist`, `TbmNoticeCreate`, `TbmNotice`, `TbmTranscript`, `TbmCheckRequest`, `TbmItemResult`, `TbmCheckRecord`를 더했고, `HistoryEventKind`에 `tbm_checked`를 더했습니다. `HistoryEventKind` 타입(`20261109-F5-share-history.md`)이 먼저 필요합니다.
- 쓰는 곳 / 까닭: 새 화면 "TBM 확인". 그날 전달할 항목 체크리스트, 녹음 업로드, 빠진 항목 강조, 원청의 공지 추가. 이력 화면에는 `tbm_checked` 줄이 함께 나옵니다.

## 화면 흐름

1. `GET /api/tbm/checklist`로 업체·날짜의 전달 항목을 보여 줍니다.
2. 녹음 파일과 동의 여부를 `POST /api/tbm/transcribe`로 보내 전사문을 받습니다. CPU판은 녹음 길이의 2~3배 걸리므로 진행 중 표시가 필요합니다. 업로드 화면에 "참석자 동의 필요, 원본은 받아쓴 뒤 삭제, 전사문은 기록으로 저장"을 적어 주세요.
3. 전사문을 `POST /api/tbm/checks`로 보내 항목별 결과를 받습니다. `missing_ids`에 든 항목을 강조하고, `mentioned`가 `true`인 항목은 `quote`를 근거로 보여 줍니다. `note`가 있으면 함께 표시합니다.

- 음성 서버가 꺼져 있으면 전사문 입력란에 글을 직접 넣어 3번부터 진행할 수 있게 해 주세요.
- 3번이 503이면 전사문을 지우지 말고 다시 시도할 수 있게 해 주세요.

## API

협력사로 볼 때는 `contractor`에 업체명을 넣습니다. 원청은 비워 둡니다. 단, `checklist`의 `contractor`는 항상 필수입니다.

| 경로 | 메서드 | 요청 | 응답 | 권한·오류 |
|---|---|---|---|---|
| `/api/tbm/checklist` | GET | `?contractor=&on=YYYY-MM-DD` | `TbmChecklist` | 그 업체에 공유된 내용만 |
| `/api/tbm/notices` | POST | 본문 `TbmNoticeCreate` | `TbmNotice` | 원청만, 협력사는 403 |
| `/api/tbm/transcribe` | POST | multipart `file`, `consent` | `TbmTranscript` | 동의 없음·지원하지 않는 형식 422, 음성 서버 실패 503 |
| `/api/tbm/checks` | POST | `?contractor=`, 본문 `TbmCheckRequest` | `TbmCheckRecord` | 협력사는 자기 업체만(403), 전달 항목 없음 422, LLM 실패 503 |
| `/api/tbm/checks` | GET | `?contractor=` | `TbmCheckRecord[]` (최근순) | 협력사는 자기 업체 기록만 |

- 녹음 형식: `.wav`, `.m4a`, `.mp3`, `.webm`, `.ogg`
- 같은 업체·날짜·문장의 공지를 다시 보내면 오류 없이 처음 기록을 돌려줍니다.
- 전달 항목은 서버가 만듭니다. `POST /api/tbm/checks`에 항목을 보내지 않습니다.

## `types.ts`에 이렇게 추가·수정해 주세요

```ts
// HistoryEventKind 유니온에 값 하나 추가 — 반영됨 (feat/F5-field-records 에서 "field_record" 와 함께 넣음)
//   | "tbm_checked"

export type TbmItemKind = "adjustment" | "risk_window" | "notice";

export interface TbmItem {
  id: string;
  kind: TbmItemKind;
  text: string;
  rule_ids: string[];
  legal_basis: string[];
  conflict_ids: string[];
}

export interface TbmChecklist {
  contractor: string;
  date: string; // YYYY-MM-DD
  items: TbmItem[];
}

export interface TbmNoticeCreate {
  contractor: string;
  date: string; // YYYY-MM-DD
  text: string;
  created_by: string;
}

export interface TbmNotice {
  id: number;
  contractor: string;
  date: string; // YYYY-MM-DD
  text: string;
  created_by: string;
  created_at: string;
}

export interface TbmTranscript {
  transcript: string;
  model: string;
}

export interface TbmCheckRequest {
  contractor: string;
  date: string; // YYYY-MM-DD
  transcript: string;
  checked_by: string;
}

export interface TbmItemResult {
  item: TbmItem;
  mentioned: boolean;
  quote: string | null; // 전달을 뒷받침하는 전사문의 문장
  note: string | null; // LLM 답을 규칙이 뒤집은 까닭
}

export interface TbmCheckRecord {
  id: number;
  contractor: string;
  date: string; // YYYY-MM-DD
  checked_by: string;
  checked_at: string;
  transcript: string;
  results: TbmItemResult[];
  missing_ids: string[]; // 전달이 확인되지 않은 항목
  provider: string;
  model: string;
}
```
