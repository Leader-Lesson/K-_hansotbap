# 3D 연결 데이터 규격 — 작업계획서·작업표준서에 무엇이 어떤 꼴로 있어야 하나

> 작성 2026-11-09. 협력사 작업계획서(F1)와 원청 작업표준서(F8)에서 뽑은 값을 고로 3D(`app/frontend/scene3d`)에 그대로 꽂기 위한 규격. **문서를 쓰는 사람(합성 데이터 제작)**, **추출 규칙을 고치는 사람(백엔드)**, **3D를 그리는 사람(프론트)** 이 같은 표를 본다.
> 기준 코드: `scene3d/src/adapter.js`(3D가 받는 모양), `equipment.js`(장비 목록), `workers.js`(작업자 배치), `app/backend/schemas.py` ↔ `app/frontend/src/types.ts`(데이터 계약), `parsers/table_mapper.py`·`parsers/normalize.py`(계획서 읽기 규칙). 수치 중 출처 없는 것은 `[팀 설정값]`.

## 0. 한 줄 결론

3D가 작업 하나를 그리려면 **어디(구역+방위) · 언제(날짜+시간) · 누가(업체) · 몇 명 · 무슨 장비 · 무슨 유형 · 어느 계통** 이 필요하다. 지금 계약에는 구역·날짜·시간·업체·유형·선행 조건만 있고 **방위·인원·장비·계통 4가지가 없다.** 이 문서는 그 4가지의 칸 이름·값 형식·코드표를 정한다.

## 1. 3D가 받는 작업(Task) 데이터 — 현재와 추가

`adapter.js taskFrom()`이 받는 값 기준. "상태"가 **추가**인 칸은 `schemas.py`·`types.ts`에 넣고 추출기가 채워야 3D에 간다.

| 칸 | 형식 | 계획서의 어느 칸에서 | 3D에서 쓰는 곳 | 상태 |
|---|---|---|---|---|
| `id` | 기준 일정 ID(`P34`) 또는 임시 ID | 작업명 ↔ 작업 분해표 매칭 | 작업 식별, 표준서 매칭 | 있음 |
| `contractor` | `가상-…` | 문서 머리 "업체명: X" / 머리 표 "업체명 \| X" / 표 '업체' 열 | 업체 색, 권한 필터 | 있음 |
| `name` | 글 | '작업명' 열 | 목록·말풍선 | 있음 |
| `zone_id` | 구역 코드 14개(2절 표) | '작업위치' 열의 구역 낱말 | 3D 구역 배치(`ZONE_MAP`) | 있음 |
| `start` / `end` | ISO 일시 | '기간'(또는 시작일·종료일) + '작업시간'(또는 주야간) | 시간 슬라이더, 겹침 | 있음 |
| `shift` | `day` / `night` | '주야간' 열 또는 시간으로 추정 | 낮/밤 표시 | 있음 |
| `hazards` | `hot_work` `confined` `height` `heavy_lift` `gas` | '위험작업·필요허가' 열 + 작업명 낱말 | 장비 켜기(HOT→용접기·가스 용기, LIFT→크레인·호이스트 …), 위험 종류 | 있음 |
| `predecessors` | 기준 일정 ID 목록 | '선행조건' 열 (`P22 완료 후` 또는 작업명) | 선행 조건 카드, 순서 위반 | 있음 |
| **`headcount`** | 정수(명) | '인원·투입인원·작업인원' 열 | 작업자 인형 수(`crew`), 구역 배너 인원, 상황판 합계 | **추가** (지금은 읽고 버림) |
| **`location_detail`** | `{text, dirs, level}` — 3절 | '작업위치' 열의 구역 뒤 낱말 | 작업자·장비를 구역 안 그 방위에 배치(`place_dirs`), 출입 제한 위반 판정 | **추가** |
| **`sectors`** | `[{start, end, dirs}]` 시간대별 방위, 없으면 `null` | '시간대별 작업 위치' 표(선택) | 시간 슬라이더에 따라 위치 이동 | **추가(선택)** |
| **`equipment`** | `[{code, name, count}]` — 4절 코드표 | '투입장비' 열 또는 '투입 장비' 표 | 장비 모델 켜기(`equipment.js` `names` 매칭), 크레인·차량 규칙 | **추가** (3D는 이미 `task.equipment` 이름 매칭을 지원한다) |
| **`system`** | `N2` `BFG` `COG` `BLAST` `CW` `ELEC` `NONE` | '계통' 열 또는 작업명 낱말 | 가스 계통 색·충돌(지금은 작업명에 '질소'면 N2, 아니면 BFG로 추정) | **추가** |
| `source` | 원문 위치 표식 | 파서 | 근거 보기 | 있음 |

### 추출 규칙(추가 칸)

- `headcount`: 열 값에서 첫 정수. "12명", "12", "8(주)+4(야)" → 12, 8은 `headcount=12`가 아니라 **합계 12**로 두고 원문을 `raw.headcount`에 남긴다.
- `location_detail.dirs`: 3절 낱말 규칙으로 `["N","E","S","W"]`의 부분집합. 낱말이 없으면 `null`(= 구역 전체, 화면에 "방위 미기재").
- `equipment`: 쉼표·가운뎃점으로 나눈 뒤 4절 코드표의 동의어로 `code`를 정한다. 코드표에 없는 말은 `code=null, name=원문`으로 남기고 3D는 그리지 않는다. 대수는 "2대", "×2", "2기", "2조"에서 정수.
- `system`: '계통' 열이 있으면 그대로, 없으면 작업명·위험작업 낱말로 — 질소·N2 → `N2`, BFG·고로가스·블리더 → `BFG`, COG → `COG`, 송풍·열풍 → `BLAST`, 냉각수 → `CW`, 전기·통전·LOTO 해제 → `ELEC`, 그 외 `NONE`.

## 2. 구역 코드표 (계획서 낱말 → 구역 → 3D 구역)

`zones.csv` 14개 ↔ 3D 모형 구역(`ZONE_MAP`). 계획서에는 왼쪽 "계획서에 쓰는 낱말" 중 하나가 **반드시** 있어야 한다(없으면 구역 미정으로 확인 필요).

| 구역 ID | 계획서에 쓰는 낱말(`normalize.py ZONE_ALIASES`) | 3D 구역 | 비고 |
|---|---|---|---|
| TOP | 노정, 장입설비, 벨리스, 노정 플랫폼 | `TOP` 노정 데크 | |
| STACK | 노흉, 샤프트 | `IN-UP` 노흉 내부 | 노 내부 수직 공동 |
| BELLY_BOSH | 노복, 조안, 보시 | `IN-MID` 노복·조안 내부 | |
| TUYERE | 풍구, 환상관, 송풍지관 | `EX-TUY` 풍구 레벨 외곽 플랫폼 | 노 안쪽 풍구층(`IN-TUY`)은 아직 안 씀 |
| HEARTH | 노상, 노저, 노바닥 | `IN-HEARTH` 노저 내부 | |
| SHELL | 철피, 노체 외부, 노체 철피 | `EX-MID` 철피 외부 중부 작업대 | 높이 구분 없음. 상부 작업대 `EX-UP`은 아직 안 씀 → **`level`에 "상부"가 있으면 `EX-UP`으로** (프론트 반영 필요) |
| CASTHOUSE | 주상, 출선장, 출선구, 탕도 | `CAST` 주상 | |
| SLAG | 슬래그, 수재설비 | `CAST` (주상과 합침) | |
| DOWNCOMER | 상승관, 하강관 | `GAS` 가스 설비 | |
| GCP | 제진기, 가스청정 | `GAS` | |
| STOVE | 열풍로 | `STOVE` | 열풍로 2·3호 구분 없음 → `level`에 호기 |
| CRANE_PAD | 크레인 기초, 인양 구역, 크레인 패드 | 없음 (목록 '지상·기타') | 대형 크레인은 3D에 고정 배치 |
| YARD | 야드, 조립장, 자재장, 적치장 | 없음 | |
| ALL | 전 구역, 전구역, 노 전체 | 없음 | 가능하면 구역별로 쪼개 적는다 |

## 3. 구역 안 위치(방위·단) 낱말 규칙

3D는 구역을 북·동·남·서 4방위(각 ±45°)로 나눈다(`workers.js DIR_Q`, `app.js barrierList`). 계획서 '작업위치' 칸은 **"구역 낱말 + 방위 낱말 (+ 단·높이)"** 순서로 쓴다.

| 쓰는 낱말 | `dirs` | 예 |
|---|---|---|
| 북측 / 북쪽 / N | `["N"]` | 노흉 승강로 북측 |
| 동측 / 동쪽 / E | `["E"]` | 노정 플랫폼 동측 (호퍼 하부) |
| 남측 / 남쪽 / S | `["S"]` | 노체 철피 외부 남측 (크레인 측) |
| 서측 / 서쪽 / W | `["W"]` | |
| 북동 / 남서 … (두 방위) | 두 개 | 주상 남동측 → `["S","E"]` |
| 전 둘레 / 전체 / 사방 | `["N","E","S","W"]` | 풍구 레벨 플랫폼 전 둘레 |
| 중앙 / 내부 중심 | `[]` + `level="중앙"` | 노저 내부 중앙 (노 내부 `in` 구역은 방위 대신 중앙 가능) |
| (없음) | `null` | 3D는 구역 전체로 그리고 "방위 미기재" 표시, 확인 필요 |

- `level`(선택): 단·높이·호기를 글로. 예 "스테이브 1~9단", "상부 작업대", "열풍로 2·3호", "풍구 12~16번". 3D는 지금 `level`을 글로만 보여 주고, SHELL의 "상부"만 `EX-UP`으로 올린다(프론트 반영 뒤).
- **시간대별 위치**가 바뀌는 작업(오전 인양·오후 용접)은 계획서에 아래 표를 더 둔다. 없으면 `sectors=null`이고 하루 종일 `location_detail.dirs`로 그린다.

| 작업명 | 날짜 | 시간대 | 위치(방위) | 하는 일 |
|---|---|---|---|---|
| 신 철피 링블록 반입·설치 | 2026-12-28 | 07:00~12:00 | 철피 외부 남측 | 블록 인양 |
| 신 철피 링블록 반입·설치 | 2026-12-28 | 13:00~17:00 | 철피 외부 남측·동측 | 가볼트 체결 |

머리글 동의어(`table_mapper.py`에 추가할 것): 시간대별 위치 표는 `시간대`+`위치(방위)` 열이 있으면 `sectors`로 읽는다.

- 코드표에 없는 큰 장비(예: 잔선 천공기, 발파 장비, 비파괴검사 장비)는 **새 모델이 필요**하다. 문서에는 원문 이름으로 쓰고 `code=null`로 둔 뒤 3D 담당에게 목록을 넘긴다.
- 3D의 `equipment.js setActive`는 이미 `task.equipment`(이름 배열)로 모델을 켠다. `adapter.js taskFrom`에 `equipment: (t.equipment||[]).map(e => e.name3d || e.name)` 한 줄을 더하면 연결된다(프론트 반영 요청으로 넘김).

## 5. 작업계획서에 꼭 들어가야 하는 칸 (협력사 양식은 자유, 칸은 필수)

머리글은 아래 동의어 중 아무거나(`table_mapper.py HEADER_SYNONYMS`; **굵은 글씨**는 새로 더할 것). 표가 아니라 문장으로 써도 LLM 경로가 읽지만, 표가 있으면 LLM 없이 읽힌다.

작성 규칙(합성 데이터):
- 모든 파일에 "합성 데이터" 문장, 협력사명은 `가상-…`, 사람 이름은 `○가상`.
- 구역 낱말은 한 칸에 하나. 방위 낱말은 3절 표의 말만.
- 장비명은 4절 동의어로. 대수는 "2대"처럼 단위를 붙인다.
- 작업명에 '노내'·'밀폐'를 쓰면 밀폐공간으로 읽히니 밀폐 작업이 아니면 피한다(예: 호이스트 운영은 "노흉 승강로"로).
- 날짜를 기준 일정과 다르게 쓸 때(시나리오)는 정답셋 `note`에 "기준 X → Y로 앞당김/연장"을 적는다.

정답셋(`answers/*.json`) 작업 항목에도 같은 칸을 둔다: `headcount`, `equipment`(`[{code,name,count}]`), `location_detail`(`{text,dirs,level}`), `system`, (선택) `sectors`.

## 6. 작업표준서 → 3D 출입 제한 표 (`app/backend/data/sop/sop_restrictions.csv`)

표준서의 "작업 금지·출입 제한"·"3D 연결" 절을 기계가 읽는 표. 한 줄이 제한 하나. 3D는 이 표 + 작업 일정으로 그 시각의 안전띠·러버콘·표지를 세운다(지금은 F2 금지 판정에서만 세운다).

| 열 | 값 | 예(SOP-P34) |
|---|---|---|
| 표준서ID | `SOP-P34` | SOP-P34 |
| 작업ID | 이 작업이 진행될 때 생기는 제한 | P34 |
| 제한ID | `표준서ID-R1` | SOP-P34-R1 |
| 구역ID | 2절 구역 코드 | TUYERE |
| 방위 | `ALL` 또는 `N,E,S,W` 부분집합, `SAME`(= 작업의 `location_detail.dirs`와 같음) | SAME |
| 제한 종류 | `ENTRY_BAN` 출입 금지 / `HOT_WORK_BAN` 화기 금지 / `GAS_IN_BAN` 가스 투입 금지 / `LIFT_PATH` 인양 경로 하부 출입 통제 / `WORK_STOP` 작업 중지 | HOT_WORK_BAN |
| 대상 | `OTHERS`(타 업체 전부) / 작업ID 목록 / 작업 유형 | OTHERS |
| 적용 시점 | `DURING`(작업 중) / `UNTIL_HANDOVER`(완료·퇴출 서명 전까지) / `BAND:07:00-12:00`(시간대) / `STEP:7`(그 단계 중) | STEP:7 |
| 범위(m) | 수치 또는 빈칸(구역 전체) `[팀 설정값]` 표시 | 11 |
| 규칙ID | R01~R30 | R04 |
| 근거 | 조문·지침 | 규칙 241조의2 |
| 3D 표시 | `TAPE` 안전띠 / `CONE` 러버콘 / `SIGN` 표지(글) / `BANNER` 구역 배너 꼬리표 / `BAR_RED` 작업 막대 금지색 | TAPE+SIGN:가스 연결 중 · 화기 금지 |
| 비고 | 자유 | 시연 S1 |

같은 표준서의 예 두 줄 더: `SOP-P34-R2 | P34 | CASTHOUSE | SAME | LIFT_PATH… → ENTRY_BAN | OTHERS | STEP:7 | — | R03 | 241조의2①2호 | CONE`, `SOP-P34-R3 | P34 | HEARTH,TUYERE,STACK | ALL | GAS_IN_BAN(착수 조건) | OTHERS | UNTIL_HANDOVER(P20·P21·P22·P27) | — | R08 | 619조②4호 | BAR_RED`.

규칙: 표준서 마크다운의 "3D 연결" 절 글과 이 표의 줄은 1:1이어야 하고, `표준서ID`·`구역ID`·`규칙ID`는 각각 `index.csv`·`zones.csv`·`conflict_rules.csv`에 있어야 한다(pytest로 검사).

## 8. 예시 — 양중C 계획서의 링블록 인양 한 줄이 Task가 되는 모습

계획서 행: `신 철피 링블록 반입·설치(대형 인양) | 노체 철피 외부 남측 (크레인 측 반원) | 2026.12.27 ~ 2027.01.03 | 07:00~17:00 | 20 | 크롤러 크레인 1,600t, 보조 크레인 250t, 다축 트레일러 2대 | 중량물, 고소 | P15 구 블록 반출, P02 크레인 조립, P03 링블록 선조립 완료 후`

```json
{
  "id": "P17", "contractor": "가상-양중C", "name": "신 철피 링블록 반입·설치(대형 인양)",
  "zone_id": "SHELL",
  "location_detail": {"text": "노체 철피 외부 남측 (크레인 측 반원)", "dirs": ["S"], "level": null},
  "start": "2026-12-27T07:00", "end": "2027-01-03T17:00", "shift": "day",
  "headcount": 20,
  "equipment": [
    {"code": "CRAWLER_CRANE_L", "name": "크롤러 크레인 1,600t", "count": 1},
    {"code": "CRAWLER_CRANE", "name": "보조 크레인 250t", "count": 1},
    {"code": "DUMP_TRUCK", "name": "다축 트레일러", "count": 2}
  ],
  "hazards": ["heavy_lift", "height"], "system": "NONE",
  "predecessors": ["P15", "P02", "P03"], "sectors": null
}
```

3D는 이 값으로 철피 외부(`EX-MID`) 남쪽 사분면에 작업자 인형 약 15명(20명 ÷ 1.3)을 두고, 대형 크롤러 크레인의 붐을 남쪽으로 돌리고, 인양 시간 동안 주상(`CAST`) 남쪽에 러버콘을 세운다(6절 `LIFT_PATH`).
