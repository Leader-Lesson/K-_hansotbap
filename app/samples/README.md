# 시연 샘플 (합성 데이터)

모든 파일은 해커톤 시연용 **합성 데이터**이며 협력사명·일정·인원은 가상이다(`가상-…`). 작업은 `app/backend/data/gy2bf_wbs.csv`(기준 일정 37개)에서 골랐고, 양식(머리글 낱말·열 순서·날짜 표기·업체명 위치)은 일부러 서로 다르게 만들었다. 다시 만들려면:

```bash
cd app/backend && uv run python ../samples/make_samples.py     # 계획서 15건 + answers/ 정답셋
cd app/backend && uv run python ../samples/accuracy.py          # 추출 정확도 (표 규칙 경로, LLM 안 부름)
cd app/backend && uv run python ../samples/accuracy.py --mode llm   # LLM 경로 (.env 의 ANTHROPIC_API_KEY)
```

## 기준 일정은 충돌 0건 — 하루를 시간대로 나눠 이어받는다

원청 기준 일정(`app/backend/data/gy2bf_wbs.csv`)은 **주간 작업만**, 작업마다 `작업시간` 칸(오전 07~12 · 오후 13~18 · 하루 07~18)을 두고 **서로 겹치지 않게** 짜 두었다. 판정은 "날짜 × 하루 작업 시간대"로 본다(`rules/overlap.py`). 같은 날 같은 구역이라도 오전·오후로 나누면 겹치지 않고, 끝과 시작이 맞닿는 인계는 겹침이 아니다.

- 노저(12-08~12-23): **내화H 잔선 천공·장약 07~12 → 내화H 발파 12~13(전원 대피) → 해체G 파쇄물 반출 13~17** (P13 을 세부 작업 P13-1~3 으로 나눔, 39행)
- 노 안 위아래 구역은 오전·오후로 나눈다 (예: 노정 기계E 오전 / 노흉 해체G 오후)
- 계획서에 같은 기준 작업 행이 여럿이면 세부 작업 ID(P01-1 …)가 붙고, 제출하면 기준 한 덩어리 대신 그 행들로 판정한다

`tests/test_samples.py::test_base_files_add_no_conflicts_and_overlap_files_do` 가 위 두 묶음을 확인한다. 모두 LLM 없이 표 규칙으로 읽힌다(근무 칸의 "주간 07:00~12:00" 시각도 읽는다).

- 양식 변형 `variants/`·통일 양식 `uniform/` 은 추출 정확도 시험용이라 **예전 날짜 그대로**다(시연에 올리지 않는다)

## 정답셋 `answers/`

파일마다 같은 이름의 JSON: 업체 · 작업명 · 구역 ID · 시작/종료일 · 주야간 · 인원 · 작업 유형 · 선행 작업 · 기준 일정 ID, 그리고 `expected_conflicts`(이 계획서가 내야 하는 충돌과 규칙 ID). `accuracy.py` 가 10칸(인원 포함)을 비교해 정확도 %와 틀린 칸 목록을 낸다. 틀린 칸 목록은 프롬프트·규칙 수정용으로 백엔드에 넘긴다.

- 정답이 `null` 인 칸(예: "주야간" 연속 작업의 주야 구분)은 세지 않는다
- 알려진 한계: 기준 ID 하나(P30)를 두 작업이 나눠 쓰는 경우 작업명이 기준 작업명과 많이 다르면(비계N '노흉 내부 작업 비계 해체') 기준 ID가 안 붙는다. 가설A(P01 3행)·전기M(P29 3행)처럼 기준 작업명 낱말을 남기면 모든 행에 붙는다

## TBM 녹음 `tbm/` (F7)

- `TBM_2027-02-26_가상-배관O_합성음성.m4a`(81초) / `…_16k.wav`(whisper.cpp 직접 입력용): macOS 음성 합성(say, Yuna)으로 만든 **합성 음성**이다. 사람 목소리 녹음이 아니므로 동의서가 필요 없다
- `TBM_대본_…md`: 읽은 대본. 원청이 공유한 4항목 중 **위험 시간대 1건을 일부러 뺐다**
- `TBM_2027-02-26_expected.json`: 공유 항목 4건과 빠져야 하는 항목(`expected_missing`). F7이 녹음 → 글 → 항목별 언급 여부를 판정할 때 정답으로 쓴다
- 실제 목소리로 바꾸려면 대본을 읽어 녹음하고(참여자 동의) 같은 이름으로 바꿔 둔다. 원본 녹음은 `recordings/`(git 제외)에 둔다

## 지난 6일치 현장 기록 `history_seed.json` (F5)

- 교대 인계·TBM 확인·착수 승인·잔업·조정·공유·지연 보고·반려/재제출 등 30건. `npm run seed` 가 이력(`/api/history`, 엑셀 내보내기)에 '현장 기록'으로 넣는다
- 프론트 시안 이력 탭의 기록을 백엔드 업체(가상-…)·규칙(R01~R30)·일정(S1 장면 2/26 직전 6일)으로 옮겼다. 사람은 직함만 쓴다
- 남긴 시각은 seed 를 돌린 날 기준 1~6일 전(`days_ago`), 내용 속 날짜는 공정 일정 날짜. 판정·조정 표에는 들어가지 않으므로 충돌 판정에 영향이 없다
- 승인·보류·반려는 원청 사람이 내린 결정으로 적는다(시스템은 작업을 승인·중지하지 않는다)
